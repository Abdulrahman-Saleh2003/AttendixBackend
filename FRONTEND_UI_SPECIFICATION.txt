مرحباً! هذا الملف هو الدليل المرجعي الشامل (Prompt & Specification Sheet) لتصميم وتطوير واجهات المستخدم (Frontend):
1. تطبيق الجوال الخاص بالموظف (Mobile App: Flutter أو React Native).
2. لوحة تحكم الويب للمدير والسوبر أدمن (Web Dashboard: React / Next.js / Tailwind CSS).

--------------------------------------------------------------------------------
1. فكرة وهوية المشروع (Project Overview & Concept)
--------------------------------------------------------------------------------
- اسم المشروع: «بصمتي» (Attendix).
- فكرة التطبيق: نظام حضور وانصراف ذكي، يعتمد على الأمان المتقدم لمنع التزوير والتحايل:
  1. التحقق الجغرافي (GPS Geofencing): لا يمكن التبصيم إلا إذا كان الموظف داخل النطاق الجغرافي المسموح لموقع العمل (مثل 100 متر).
  2. ربط الجهاز (Device Binding): الحساب مربوط بجهاز هاتف واحد معتمد من المدير (Installation ID + Public Key). لا يمكن التبصيم من هاتف زميل.
  3. البصمة البيومترية المحلية (Biometrics): التحقق عبر بصمة الإصبع أو الوجه لنظام الهاتف (Biometric Prompt) قبل توقيع الحركة.
  4. وقت الخادم المعتمد (Server-Authoritative): لا يتم الاعتماد على ساعة الهاتف لمنع التلاعب بالوقت.
  5. منع تكرار الطلبات (Idempotency Key): لكل حركة مفتاح فريد لمنع تكرار التسجيل عند ضعف الشبكة.

- التقنيات الخلفية (Backend Tech Stack):
  * الخادم: Django 6.x + Django REST Framework.
  * قاعدة البيانات: PostgreSQL.
  * المصادقة: JWT (JSON Web Tokens) - Access & Refresh Tokens.
  * حقل تسجيل الدخول الرئيسي: البريد الإلكتروني (Email).

- الهوية البصرية المقترحة (Visual Identity & Theme):
  * النمط: عصري، نظيف، مسطح (Clean, Modern, Corporate SaaS).
  * دعم كامل لاتجاه الواجهات من اليمين إلى اليسار (RTL First - اللغة العربية أساسية).
  * لوحة الألوان (Color Palette):
    - الأساسي (Primary): أزرق بحري احترافي (#1E40AF أو #0F172A).
    - الثانوي التفاعلي (Accent/Action): كحلي مع أزرق سماوي (#2563EB / #38BDF8).
    - النجاح والاعتماد (Success / Check-in): أخضر زمردي (#10B981).
    - الانصراف والتحذير (Danger / Check-out): أحمر وردي (#EF4444).
    - الحالات المعلقة والتنبيه (Warning / Pending): برتقالي دافئ (#F59E0B).
    - الخلفيات: رمادي ناعم خفيف (#F8FAFC) للوضع الفاتح، مع دعم Dark Mode اختياري.

2. هرمية المستخدمين والأدوار (User Roles & Access Control)
--------------------------------------------------------------------------------
1. السوبر أدمن (Super Admin) - مالك النظام:
   - تسجيل الدخول بالبريد الإلكتروني المعتمد.
   - الصلاحية الحصرية لإضافة وإدارة حسابات المدراء (Admins).
   - مراقبة سجل الرقابة والتدقيق الشامل لجميع العمليات (Audit Logs).

2. المدير (Admin / Manager):
   - تسجيل الدخول عبر لوحة تحكم الويب.
   - مراجعة واعتماد حسابات الموظفين الجدد وحالاتهم (Pending, Active, Suspended).
   - مراجعة واعتماد أجهزة الهواتف المسجلة للموظفين (Device Approvals).
   - إدارة الهيكل التنظيمي: مواقع العمل (Worksites) وإحداثياتها ونطاق الـ GPS، والورديات (Shifts) وأوقات الدوام.
   - البت في طلبات الموظفين (الموافقة/الرفض على طلبات الإجازات، المغادرة المبكرة، تصحيح البصمة، وتغيير الهاتف).
   - استعراض الإحصائيات الفورية وتقارير الحضور وتصديرها.

3. نائب المدير (Deputy Admin):
   - يمتلك صلاحيات فرعية يحددها المدير للبت في الطلبات أو إدارة الأقسام.

4. الموظف (Employee):
   - يستخدم تطبيق الجوال فقط (Android / iOS).
   - تسجيل حساب جديد وتسجيل هاتفه (ينشأ بحالة Pending حتى موافقة المدير).
   - تسجيل الحضور والانصراف والخروج المؤقت بالبصمة داخل موقع العمل.
   - استعراض سجله الشخصي لليوم والشهر.
   - تقديم ومتابعة الطلبات (مغادرة مبكرة، إجازة، تصحيح حضور، تغيير جهاز).

3. تفصيل شاشات تطبيق الجوال للموظف (Mobile App UI Screens)
--------------------------------------------------------------------------------

الشاشة 1: البداية والترحيب (Splash & Onboarding)
- شعار التطبيق «بصمتي» مع حركة بسيطة (Clean Animation).
- فحص التوكن المحفوظ تلقائياً: إذا كان مسجلاً يذهب للرئيسية، وإلا يتوجه لتسجيل الدخول.

الشاشة 2: تسجيل الدخول (Login Screen)
- حقل البريد الإلكتروني (Email) + حقل كلمة المرور (Password).
- زر «تسجيل الدخول» مع حالة تحميل (Loading Spinner).
- زر تفعيل الدخول السريع عبر البصمة البيومترية للمرات القادمة (Biometric Quick Login).
- رابط «إنشاء حساب موظف جديد» في الأسفل.

الشاشة 3: إنشاء حساب موظف جديد (Employee Register Screen)
- الحقول:
  * الاسم الكامل (Full Name).
  * الرقم الوظيفي (Employee Code - مثلاً EMP-101).
  * البريد الإلكتروني (Email).
  * رقم الهاتف (Phone).
  * كلمة المرور وتأكيدها.
  * المسمى الوظيفي (Job Title).
- زر «إنشاء الحساب».
- عند النجاح: ينتقل الموظف مباشرة إلى الشاشة التالية (واجهة اختيار المنشأة).

الشاشة 4: واجهة اختيار المنشأة وإرسال طلب الانضمام (Choose Organization & Join Request)
- شاشة تظهر بعد إنشاء الحساب مباشرة أو عند دخول موظف غير منضم:
  * حقل بحث علوي للبحث عن المنشأة بالاسم أو الكود.
  * قائمة بطاقات تفاعلية تعرض جميع المنشآت المسجلة حالياً:
    - اسم المنشأة (مثال: شركة الأفق للتقنية).
    - كود المنشأة البارز (مثال: ORG-101).
    - اسم الأدمن المسؤول (مثال: م. أحمد السعيد).
  * عند اختيار منشأة: يضغط الموظف زر «إرسال طلب الانضمام».
  * [قاعدة عمل حاسمة]: لا يمكن إرسال طلب ثانٍ إلى أي منشأة طالما يوجد طلب معلق (PENDING). إذا حاول تظهر له رسالة توضيحية:
    "لديك طلب معلق حالياً لدى [اسم المنشأة]. يرجى انتظار قرار الأدمن، وفي حال تم الرفض يمكنك اختيار منشأة أخرى."

الشاشة 4.1: شاشة متابعة حالة طلب الانضمام (Join Request Status Screen)
- تظهر أثناء انتظار قرار الأدمن:
  * في حالة الانتظار (PENDING - أصفر): أيقونة انتظار ورسالة "طلبك قيد المراجعة لدى [اسم المنشأة]" مع زر تحديث.
  * في حالة الرفض (REJECTED - أحمر): رسالة "نعتذر، تم رفض طلب انضمامك إلى [اسم المنشأة]. سبب الرفض: [تعليق الأدمن]"، مع زر بارز: [اختيار منشأة أخرى وإعادة المحاولة] ليعود لشاشة اختيار المنشآت!
  * في حالة القبول (APPROVED - أخضر): رسالة تهنئة بالاعتماد والانتقال فوراً للشاشة الرئيسية للتطبيق.

الشاشة 5: الشاشة الرئيسية - التبصيم الحي (Home / Attendance Screen)
- الرأس (Header):
  * ترحيب بالموظف باسمه، مع التاريخ الهجري والميلادي والوقت الحالي.
  * ويدجت الحالة اليومية: (حاضر، لم يسجل بعد، في استراحة).
- كرت موقع العمل والـ GPS (Geofence Card):
  * اسم موقع العمل المعتمد (مثال: فرع الرياض الرئيسي).
  * المسافة الحالية عن الموقع (مثال: "أنت داخل النطاق - 35 متراً" بلون أخضر، أو "أنت بعيد - 250 متراً" بلون أحمر).
  * مؤشر دقة إشارة الـ GPS (مثال: دقة ممتازة 8 أمتار).
- زر البصمة التفاعلي الضخم (Interactive Action Button):
  * زر دائري مريح وعصري في منتصف الشاشة مع تموجات ضوئية (Pulsing Effect).
  * يتغير نصه ولونه بذكاء حسب الحالة:
    - [تسجيل حضور CHECK IN] بلون أخضر.
    - [تسجيل انصراف CHECK OUT] بلون أحمر / كحلي.
    - زران صغيران جانبيان لـ [خروج مؤقت BREAK OUT] و [عودة من استراحة BREAK IN].
- تفاعل الزر:
  * عند الضغط يفتح فوراً فحص بصمة الهاتف البيومترية (Fingerprint / Face ID).
  * يرسل الإحداثيات وتوقيع الجهاز للخادم بوقت الخادم المعتمد.
  * يعرض شاشة منبثقة بنتيجة العملية:
    - بطاقة نجاح خضراء: "تم تسجيل الحضور بنجاح في تمام الساعة 08:02 ص".
    - بطاقة رفض حمراء مع ذكر السبب الواضح: "أنت خارج نطاق موقع العمل المسموح بمقدار 180م".

الشاشة 6: سجل الحركات الشخصي (Attendance History Screen)
- شريط علوي يوضح إجمالي أيام الحضور، الغياب، والتأخير لهذا الشهر.
- فلترة حسب الشهر والسنة.
- قائمة كروت الأيام السابقة (Day Cards):
  * تاريخ اليوم والحالة (حاضر بأخضر، متأخر ببرتقالي، غائب بأحمر).
  * وقت الدخول الفعلي ووقت الخروج الفعلي.
  * إجمالي ساعات العمل في اليوم.
  * زر صغير بجانب أي حركة: "طلب تصحيح بصمة" في حال وجود نسيان.

الشاشة 7: مركز الطلبات والإجازات (Requests & Permissions Screen)
- تبويبين رئيسيين: [تقديم طلب جديد] و [طلباتي السابقة].
- أنواع الطلبات:
  1. مغادرة مبكرة (وقت المغادرة + السبب).
  2. إجازة (نوع الإجازة: سنوية، مرضية، طارئة + تاريخ البداية والنهاية + السبب).
  3. تصحيح بصمة (اختيار اليوم + نوع الحركة + الوقت المقترح + السبب).
  4. تغيير هاتف (طلب اعتماد جهاز جديد مع السبب).
- قائمة الطلبات السابقة مع بطاقة حالة ملونة لكل طلب:
  * أصفر: قيد المراجعة (Pending).
  * أخضر: تمت الموافقة مع تعليق المدير (Approved).
  * أحمر: مرفوض مع ذكر سبب الرفض (Rejected).

الشاشة 8: الملف الشخصي والإعدادات (Profile & Settings)
- معلومات الموظف، المسمى الوظيفي، الرقم الوظيفي، والقسم.
- معلومات الهاتف المسجل (الموديل، حالة الاعتماد، معرّف التثبيت).
- خيار تغيير كلمة المرور.
- زر تسجيل الخروج.

4. تفصيل شاشات لوحة تحكم الويب للمدير والسوبر أدمن (Web Dashboard UI)
--------------------------------------------------------------------------------

أ. لوحة السوبر أدمن (Super Admin Portal):
-----------------------------------------
1. شاشة إدارة المدراء (Admins Management):
   - جدول أنيق يعرض جميع المدراء ونواب المدراء.
   - الأعمدة: الاسم، البريد الإلكتروني، رقم الهاتف، الدور (مدير / نائب مدير)، الحالة (نشط / معطل)، وتاريخ الإنشاء.
   - زر علوي: [+ إضافة مدير جديد] يفتح نافذة Modal لإدخال الإيميل، الاسم، كلمة المرور، والدور.
   - أزرار التحكم لكل مدير: (تعديل الصلاحيات، إيقاف مؤقت، حذف/تعطيل).
2. شاشة السجل الرقابي العام (System Audit Logs):
   - جدول زمني (Timeline Table) بكل حركة أمنية أو إدارية في النظام: (من قام بماذا، نوع الكيان، التوقيت، وعنوان الـ IP).

ب. لوحة المدير (Manager / Admin Portal):
----------------------------------------
1. لوحة المؤشرات الرئيسية (Executive Dashboard):
   - كروت إحصائية علوية بأرقام كبيرة وأيقونات ملونة:
     * الحاضرون اليوم (عدد ونسبة مئوية بلون أخضر).
     * المتأخرون اليوم (بلون برتقالي).
     * الغائبون اليوم (بلون أحمر).
     * طلبات الموظفين المعلقة بانتظار قرارك (Pending Requests).
     * أجهزة الهواتف المعلقة بانتظار الاعتماد (Pending Devices).
     * حسابات الموظفين الجدد بانتظار التفعيل.
   - جدول المراقبة الحية (Live Attendance Feed): يعرض حركات الحضور لحظة بلحظة مع خريطة مصغرة للموقع.
   - مخطط بياني (Chart): نسبة الالتزام الأسبوعية أو الشهرية للمؤسسة.

2. شاشة إدارة واعتماد الموظفين (Employees Management):
   - فلاتر سريعة: [الكل]، [المعلقون بانتظار الاعتماد Pending]، [النشطون Active]، [الموقوفون Suspended].
   - قائمة الموظفين مع معلوماتهم (الرقم الوظيفي، الاسم، القسم، الوردية، موقع العمل، الهاتف).
   - عند الضغط على موظف معلق: نافذة لاتخاذ قرار [قبول وتفعيل] أو [رفض] مع تعيين الوردية وموقع العمل له.

3. شاشة إدارة واعتماد الأجهزة (Registered Devices):
   - جدول يوضح الهواتف المسجلة: الموظف، موديل الهاتف (مثل iPhone 15 Pro, Galaxy S24)، معرّف التثبيت، وحالة الجهاز.
   - أزرار سريعة: [اعتماد الهاتف كجهاز نشط للموظف] أو [إلغاء الاعتماد Revoke].

4. شاشة مواقع العمل والنطاق الجغرافي (Worksites & Geofencing):
   - خريطة تفاعلية (Google Maps أو Leaflet / OpenStreetMap).
   - إمكانية إضافة موقع عمل جديد بالنقر على الخريطة لتحديد خط الطول والعرض تلقائياً.
   - شريط تحكم دائري لتحديد نصف القطر المسموح به للتبصيم (Radius بالمتر، مثلاً 50م، 100م، 200م) مع رسم دائرة جغرافية واضحة حول المقر.

5. شاشة إدارة الورديات وأوقات الدوام (Shifts Management):
   - بطاقات الورديات: (الوردية الصباحية، الوردية المسائية...).
   - إعدادات الوردية: وقت البدء، وقت النهاية، أيام العمل الأسبوعية، ودقائق السماح بالتأخير (Grace Period).

6. شاشة البت في الطلبات والإجازات (Requests Approval Hub):
   - عرض الطلبات مع تنبيه فوري بالطلبات المعلقة.
   - تفاصيل كل طلب (اسم الموظف، نوع الطلب، السبب، التاريخ، والمرفقات إن وجدت).
   - زران واضحان: [موافقة باللون الأخضر] و [رفض باللون الأحمر] مع حقل لكتابة تعليق المدير.

7. شاشة سجلات الحضور الشاملة والتقارير (Reports & Export):
   - جدول متقدم مع بحث وفلترة دقيقة (باسم الموظف، القسم، الموقع، أو الفترة الزمنية).
   - عرض المسافة المحسوبة، دقة الـ GPS، وحالة الاعتماد.
   - زر علوي: [تصدير إلى Excel / CSV / PDF].

5. دليل الـ API ومطابقة الحقول (Backend API Specifications for Frontend)
--------------------------------------------------------------------------------

الرابط الأساسي (Base URL):
- التطوير المحلي: http://127.0.0.1:8000
- الترويسة الإلزامية للطلبات المحمية:
  Authorization: Bearer <ACCESS_TOKEN>
  Content-Type: application/json

1. تسجيل الدخول (Login):
- المسار: POST /api/accounts/login/
- جسم الطلب (Body):
  {
    "email": "employee@example.com",
    "password": "Password123"
  }
- الرد الناجح (200 OK):
  {
    "access": "eyJhbGciOi...",
    "refresh": "eyJhbGciOi...",
    "user": {
      "id": "uuid",
      "email": "employee@example.com",
      "full_name": "أحمد محمد",
      "role": "EMPLOYEE",         // أو SUPER_ADMIN أو ADMIN أو DEPUTY_ADMIN
      "account_status": "ACTIVE", // أو PENDING
      "is_super_admin": false,
      "is_admin": false
    }
  }

2. تسجيل حساب موظف جديد من الموبايل (Register):
- المسار: POST /api/employees/register/
- جسم الطلب:
  {
    "email": "user@example.com",
    "password": "StrongPassword123",
    "full_name": "سالم العلي",
    "phone": "0501234567",
    "employee_code": "EMP-204",
    "job_title": "مطور برمجيات",
    "department_id": "uuid-اختياري"
  }

3. تسجيل جهاز الهاتف للموظف (Device Registration):
- المسار: POST /api/employees/devices/register/
- جسم الطلب:
  {
    "installation_id": "unique-uuid-generated-on-app-install",
    "public_key": "device-public-key-string",
    "manufacturer": "Samsung",
    "model": "Galaxy S23",
    "os_version": "Android 14"
  }

4. تسجيل حركة البصمة (Check-in / Check-out):
- المسار: POST /api/attendance/record/
- جسم الطلب:
  {
    "event_type": "CHECK_IN", // الخيارات: CHECK_IN, CHECK_OUT, BREAK_OUT, BREAK_IN
    "installation_id": "same-device-installation-id",
    "latitude": 24.7135517,
    "longitude": 46.6752957,
    "accuracy_m": 12,
    "biometric_method": "LOCAL_FINGERPRINT",
    "idempotency_key": "unique-uuid-per-button-click-to-prevent-duplicates"
  }
- الرد عند القبول (201 Created):
  {
    "detail": "تم معالجة حركة البصمة بنجاح.",
    "event": {
      "id": "uuid",
      "event_type_display": "تسجيل حضور",
      "server_timestamp": "2026-11-03T08:00:15+03:00",
      "distance_m": 24.50,
      "verification_status": "ACCEPTED"
    }
  }
- الرد عند الرفض (400 Bad Request):
  {
    "detail": "أنت خارج نطاق موقع العمل المسموح (المقر الرئيسي)، المسافة: 280م، النطاق المسموح: 100م."
  }

5. إحصائيات لوحة التحكم للإدارة (Dashboard Stats):
- المسار: GET /api/attendance/admin/dashboard-stats/
- الرد (200 OK):
  {
    "date": "2026-11-03",
    "total_employees": 45,
    "present_today": 38,
    "absent_today": 7,
    "pending_requests": 4,
    "pending_devices": 2,
    "pending_employee_accounts": 3
  }

6. تعليمات إرشادية للمصمم ومطور الواجهات (Frontend & AI Guidelines)
--------------------------------------------------------------------------------
1. الهواتف القديمة وضعف الـ GPS:
   - يجب أن تعرض الواجهة للموظف مؤشر دقة إشارة الـ GPS قبل الضغط على الزر، مع تنبيه لطيف "يرجى الانتظار ثوانٍ حتى يتم التقاط موقعك بدقة".
2. منع الضغط المتكرر (Debounce & Idempotency):
   - عند ضغط زر البصمة، يتم تعطيل الزر فوراً وإظهار مؤشر تحميل ناعم وتوليد UUID جديد كـ `idempotency_key`.
3. الاستجابة دون إنترنت:
   - في حال عدم وجود اتصال، يعرض التطبيق رسالة واضحة: "تعذر الاتصال بالخادم، لم يتم تسجيل الحضور بعد، يرجى المحاولة عند توفر الإنترنت".
4. تجربة المستخدم في لوحة التحكم (UX for Admin):
   - جداول البيانات يجب أن تحتوي على بحث سريع، فرز، ترقيم صفحات (Pagination)، وتحميل هيكلي (Skeleton Loaders) أثناء جلب البيانات.
   - تأكيدات الحذف والتعطيل تظهر في نوافذ تأكيد جميلة (Confirmation Dialogs) لتفادي الأخطاء.
